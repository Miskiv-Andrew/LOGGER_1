# Наземное ПО системы «ДРОН-1»

Этот файл Claude читает в начале каждой сессии. Здесь — контекст проекта, роли, правила работы и ключевые факты.
Подробности — в документах из папки `docs/` (список в конце).

## 1. Проект

- **Что делаем:** наземное программное обеспечение (НПО) оператора радиационной разведки для работы с дроном «ДРОН-1» через радиолинию.
- **Платформа:** Qt / C++, Windows, рабочий компьютер оператора.
- **Этап 1 (упрощённый):** до 31.12.2026. Состав — документ `docs/Наземное ПО — этап 1, функции и распределение работ.docx`.
- **Этап 2 (расширенный):** лето 2027 (идентификация нуклидов, PDF-отчёты, GeoJSON/KML/N42.42, планирование галсов, воспроизведение во времени).
- **Условия:** 1 станция — 1 дрон — 1 оператор; карты офлайн (тайлы на диске); хранение — SQLite; интерфейс на украинском и английском; шифрование радиоканала обеспечивает радиомодем (НПО работает с COM-портом).

## 3. Правила работы с Claude

1. Делать только то, о чём просят. Без набросков и кода по своей инициативе. Сначала обсуждение, код — по прямой команде («давай код»).
2. Код выдаётся целыми функциями или классами: файл, функция, что удалить (строки и якорь), что вставить. При нескольких правках в файле — порядок снизу вверх.
3. Чужой код и комментарии не переписывать и не переформатировать — меняется только необходимое.
4. Один этап за раз: разработчик пишет или вставляет код, собирает, коммитит и пушит; Claude проверяет коммит (сверка с договорённым, синтаксис) и отвечает таблицей «что проверено — итог».
5. Claude не коммитит и не пушит.
6. Возможен режим «Claude описывает задачу — разработчик пишет — Claude проверяет»: тогда описание даётся таблицей «ПРОБЛЕМА — ПОСЛЕДСТВИЯ — РЕШЕНИЕ» или «вопрос — ответ».
7. Документы — Word-файлом (.docx), по пунктам; таблицы — в Word, не в markdown. Язык общения и документов — русский. Комментарии в коде — на русском. Интерфейс — uk/en.
8. Факты о логгере и протоколе — только по коду и документам. Если что-то неизвестно — не выдумывать, а записать в «Открытые вопросы».
9. Ответ — кратко и по делу; если ошибся — признать и исправить без лишних извинений.

## 6. Ключевые факты протокола (подробно — «Протокол обмена для наземного ПО»)

- **Порт:** 115200 8N1. **Пакет:** `AA 55 AA 55 | ID | Length (uint16 LE) | Payload | CRC16 (LE) | 0D 0A 0D 0A`, длина 13 + Length. Пакет «без данных»: Length = 1, Payload = 0x01.
- **CRC16:** CCITT-FALSE (полином 0x1021, начало 0xFFFF, без отражения), по ID + Length + Payload. Проверка: «123456789» → 0x29B1.
- **Приём на земле:** искать начало по маркеру; длину брать из Length, конец проверять на месте; логгер шлёт каждый пакет 2–5 раз подряд (коэффициент дублирования) и после каждой копии `00 00`; копия = тот же пакет не позже 1 с после предыдущего.
- **Передача команд:** логгер выполняет только первую команду пачки (пачка = без паузы 100 мс); **следующую команду — только после ответа на предыдущую**; повтор без ответа — не раньше 20 с; **первые 60 с после включения логгер команды не принимает**.
- **Ответы:** ID01 — выполнено; ID02 — ошибка пакета, неизвестный ID или неверный Payload; ID03 — запрещено в режиме или не выполнено условие. Режим проверяется раньше Payload.
- **Режимы логгера:** проверка → ожидание → разведка → возвращение; авария — выход только выключением питания. Режим не сообщается явно — определяется по событиям.
- **Данные:** ID19/ID20 (координата, время, 11 байт), ID22 (измерение, 31 байт), ID23 (порция спектра, 2055 байт; итоговый спектр — только на SD, 2070 байт), ID27 (начало спектра, 22 байта), ID25 (тип отказавшего прибора), ID24 (спуфинг), ID28 (не удалось запустить спектр). Отладочные ID70–ID84 — в отладочной сборке логгера (сейчас включена).
- **SD:** `0:/ГГММДД/ЧЧММСС.CSV` (UTC), строка `ID,XX,XX,…` в HEX без Length и CRC; один файл на одну область (ID04).

## 7. Что берём из имитатора

CRC16 и сборка пакета, приём радиолинии с отсевом копий, разбор сообщений и тексты ответов, формирование команд ID01–ID14, разбор SD и сверка, проверка точки в многоугольнике, график спектра (QCustomPlot), карта (`Viewermap`, `mapcore`) — оценить для офлайн-тайлов.

## 8. Открытые вопросы

Протокол: (1) причина остановки набора спектра не передаётся — решено добавить сообщение, ID и формат не определены; (2) авария во время радиомолчания — земля ничего не узнает (ID14 в аварии запрещён).
Этап 1: формат тайлов на диске; коэффициенты пересчёта ПАЕД на 1 м; расшифровка байта состояния БДБГ (Stat); пороги тревог по умолчанию; параметры интерполяции; UTC или местное время; как НПО узнаёт о включении дрона (блокировка 60 с); энергетическая калибровка БДБГ-15 (этап 2).
Логгер: отключить `DEBUG_MODE` в лётной сборке; этап I (CubeMX, аппаратная часть) не выполнен.
